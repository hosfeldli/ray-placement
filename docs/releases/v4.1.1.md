# Lima 4.1.1 — From Search to Action

This incremental release publishes the completed Browser, Search, task-progress, Terminal, and Messages changes requested on November 2, 2026. It does not close the remaining broad Browser, Workbench, Mail/Messages, or live-device acceptance gates.

## New Features

- **Ask Lima from Search:** Select the sparkles action, type a request, and press Return to create and start a new chat in the Assistant window. An already-typed search can become a prompt. A running chat is not interrupted; an unsent Search prompt is retained if a new run cannot start yet.
- **Visible task checklists:** Multi-step work can use persistent pending, working, completed, and blocked steps. Updates require stable IDs, current revisions, and completion evidence. Unfinished plans receive up to two continuation prompts; blocked or still-unfinished work remains visibly incomplete.
- **Terminal work log:** See the session's goal, checklist, and recent recorded activity above real terminal output. Switching surfaces retains the same processes and conversation ownership.

## Improvements and Fixes

- Smooth tool selection and short Search/workspace transitions that respect Reduce Motion.
- Independent Browser access persists across pages and later messages in its chat, with revocation and isolation from other chats and saved-task overrides.
- Website click handlers, submit activation, pointer-driven widgets, date fields, dynamic-page targets, and hidden-dialog detection work more reliably.
- Semantic extraction now matches the existing 32-frame registration capacity instead of stopping at 12.
- Search's keyboard hint fits the opening window; clearing a query collapses its native background correctly.
- Messages can decode supported rich-text bodies, including long Unicode text, and search bounded rich-body candidates. Unnamed conversations use participant addresses. The transcript uses chronological bubbles with selected-result positioning and a Latest action.

## Validation

All 819 discovered Swift tests passed. Six final focused checks also passed after strengthening the existing-install migration fixture. Visual review covered 36 Search renders and 40 checklist, terminal work-log, and Messages transcript renders across themes, widths, and enlarged text.

The live, non-booking Fogo check passed public navigation to Reservations, opening a date picker, choosing a calendar day, and protected screenshot capture with 15 accounted-for frames. A local embedded reservation fixture completed through its confirmation. No availability request, personal details, or real reservation submission was made.

Exact-version CI, hosted signing, integrity checks, and public-asset verification are required before publication.

## Known Limitations

This is an implemented-subset release, not completion of all acceptance gates. Checklist completion evidence is reported by the assistant and is not independent proof of an external transaction. The same chat must finish its active run before Search can start another one.

Messages changes were verified with isolated fixtures; no personal history was read and no real messages were sent during validation. The rich-text decoder supports common envelopes rather than every possible archived format. Message search inspects at most 1,000 scoped candidates. Messages sending remains text-only with exact review; attachment sending and continuous incoming monitoring remain unsupported. Existing Mail live-acceptance limits remain open.

Scheduled tasks still require Lima to be running and the Mac awake. Cloud transcription uses rolling windows; speaker labels are window-scoped, and local speaker names are manual. Live microphone/API accuracy, game completion, and installed-update acceptance remain unverified. Protected inputs, payment commitments, native permissions, and signed-update verification retain their existing boundaries.
