# Lima v3.14.26 — visible AI workspaces and connected tool flow

This is a limited incremental release of the current Lima UI and AI-tool changes. **It is not the completed project-centered AI Workbench or the full Search/accessory overhaul.** The requester explicitly directed publication after being told that live-window behavior and broader scope were not fully verified.

## Included

- Foreground AI Browser actions request presentation of Lima's shared Browser workspace and report whether the window was observed visible. Background research tabs remain deferred. Navigation tools wait for a new WebKit completion and a stable semantic page, returning a structured failure rather than claiming an unverified page state.
- `terminal_start` requests presentation of the shared Terminal and selects the AI-created session. The Terminal now has clearer session, status, and stopped-personal-shell states; AI sessions remain visible in the same surface the user can inspect.
- AI activity displays a connected sequence of recorded tool calls, parallel-agent branches, child calls, and matching approval states instead of a flat series of checks and Xs. Existing bounded concurrent child execution remains in place.
- Tool-first guidance encourages useful routed actions and verification across API and CLI providers without bypassing access controls or making pointless calls. Codex CLI continuations can receive a bounded, ephemeral Browser JPEG from the latest tool-result turn; Claude CLI remains text-only.
- Streaming text-completion signals allow formatted answer text to appear before a delayed provider terminal event. A shorter post-text watchdog bounds that wait. Grammar progress runs in the shared lower activity shelf and ends with the Grammar task rather than leaving a detached working toast.
- Browser tabs/address UI and Terminal status styling received a visual pass.

## Known incomplete or unverified scope

- A live AI run has **not** confirmed that the Browser or Terminal opens correctly in a real Lima window on the user's machine. Offscreen renders and model-level tests are not a substitute for that interaction test. The reported no-response and lingering-writing symptoms have not been reproduced and proven fixed in that environment.
- Persistent project-centered workspaces, attached-folder bookmarks and authority, conversation-independent PTYs, broad native file/Git/web/document/data tools, a unified run/artifact/verification architecture, and complete end-to-end Workbench acceptance remain unfinished.
- Browser page-state preservation during tab suspension, real-site popup/frame/clipping/accessibility/sensitive-action validation, and full live-provider compatibility remain incomplete. Some Browser behavior is constrained rather than fully verified.
- The broader Search/accessory/API-key-AI overhaul and the unavailable earlier Search/Workspace proposal have not been fully audited or implemented. Grammar's external-API default is documented, but this release is not proof that every accessory follows that preference.
- Real-window frame pacing and memory comparisons against v3.14.24 for Search, AI streaming, Workspace switching, Notes editing, resizing, and realistic Browser loads remain undone.

## Verification before release

- The current source tree passed a Debug build, **494 local Swift tests**, and `git diff --check`.
- Two opt-in live Codex CLI tests passed: routed native-tool execution through Lima, and choosing a useful routed tool without an explicit command to call it.
- The expanded offscreen visual audit reported **zero failed renders**, including Browser, Terminal, Grammar, and connected parallel-agent activity fixtures. This is not a live interaction or performance result.
- The hosted release workflow must still pass exact-commit CI, optimized build, signing, artifact verification, and remote digest checks before public publication.

Open complete-scope gates remain in `docs/EMBEDDED_BROWSER_RELEASE_GATE.md`. Do not describe this release as full completion of every request since v3.14.25.
