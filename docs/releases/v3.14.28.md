# Lima v3.14.28 — Grammar CLI and agent workspace

This is a **limited release** of the implemented Grammar CLI and agent-workspace changes, not completion of the full Browser or AI Workbench acceptance plan. The requester explicitly directed publication with the remaining limitations disclosed in `docs/EMBEDDED_BROWSER_RELEASE_GATE.md`.

## Included

- Fix Writing and Grammar can use Codex CLI or Claude CLI through a shared inference boundary, without AI Chat history or Lima tools. Codex Grammar uses fresh ephemeral turns on a bounded pool of persistent app-server processes; its separate process home excludes user MCP servers, plugins, skills, and instructions while retaining the existing CLI sign-in. Claude Grammar requests no tools. CLI errors remain visible rather than silently switching to a paid API or Harper. Existing HTTP-provider routing and opt-in Harper fallback remain available for HTTP providers.
- Grammar settings use the shared provider and model catalog. CLI providers show installation and connection status instead of API-key or base-URL controls. Candidate ensembles, adjudication, correction safety checks, and cancellation remain in the Grammar path.
- AI execution continues according to task state rather than a fixed tool-round or total subagent count. Concurrency and output bounds remain, with recovery feedback for repeated failures without progress.
- The embedded Browser adds generic `browser_activate`, clearer semantic target kinds and available actions, background verified-link activation, and suspended logical tabs while retaining a six-live-WebView cap. Fresh-target, authority, sensitive-action, and verified-destination protections remain.
- The Browser has native AI focus, pointer, tab-state, and activity presentation. A persistent AI sidecar shares the existing conversation model with the full AI workspace.

## Validation and limits

- The final development tree passed 517 Swift tests, a Release build, `git diff --check`, the deterministic Workbench gate and its signed-in live Codex check, a separate live Codex Grammar connection test, and an offscreen visual audit with zero failed renders.
- Claude CLI was not installed on the development Mac, so its real authenticated inference path was **not** exercised. The fake-process test verifies no-tools CLI invocation but is not a live Claude acceptance test.
- The Browser pointer and AI sidecar were not verified through live packaged-app interaction. Offscreen renders and WebKit fixtures do not establish real-site behavior, accessibility, repaint, or production performance. The broader Browser/Workbench and response-presentation gates remain open.
- Exact-commit CI, immutable tagging, hosted signing and artifact checks, and public-release verification remain required for this version; do not claim them complete before their corresponding workflow results exist.
