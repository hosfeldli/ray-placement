# Lima 4.1.2 — Find It, Build It

This incremental release publishes the Search fixes requested on November 3, 2026, together with the completed extension-system overhaul and workspace repairs. It does not claim completion of the remaining broad Browser, Workbench, Mail/Messages, microphone, or installed-update acceptance gates.

## New Features

- **Search your notes:** Select Notes in Search to browse saved notes and search their titles, tags, and bounded content. A removable Notes chip keeps the scope visible.
- **Record from Search:** The microphone opens the dictation workspace and starts speech recording. Selecting it during an active recording opens that recording without stopping it. Existing microphone permissions and transcription settings apply.
- **One extension library:** My Extensions, Discover, and Build share package status, permission review, command switches, shortcuts, and repair diagnostics. Invalid and duplicate packages remain visible.
- **Build extensions:** Create website shortcuts, scripts, forms, and supported read-only AI tools in the app. Link source folders for manifest reloads, or use the dedicated toolkit to create, validate, run, and package extensions.

## Improvements and Fixes

- Search uses one relevance scale across local commands and saved content. Exact titles, title prefixes, title words, and explicit aliases receive priority over body matches. Usage and favorites remain bounded tie-breakers; core actions win comparable matches. Long note bodies must contain matching words rather than scattered fuzzy letters.
- Extension discovery uses asynchronous scanning and cached metadata. Running an AI extension still revalidates the current package and approval. Package switches control commands and AI contributions together; existing shortcuts and command preferences survive migration and updates.
- Improve extension argument handling, validation diagnostics, executable packaging, individual invocation cancellation, and form timeouts.
- Fix the Settings handoff from Search and recover interrupted AI continuations without repeatedly resending a rejected continuation identifier.
- Keep the Assistant helper rail out of the way when its workspace is already visible. Use the retained terminal, conversation, and browser surfaces together without duplicate terminal presentations.
- Add structured multi-field assistant forms, temporary script-free HTML reports, a terminal composer and key input, and dedicated screenshot and screen-reader shortcut settings.

## Validation

All 847 discovered Swift tests passed in the isolated regression suite, including focused relevance/provider/quick-action checks. All 10 checked-in extension manifests passed schema validation, and all four toolkit starter workflows passed. Visual review covered 48 Search renders and 24 extension-library/builder renders across themes, widths, density, and enlarged text. Signed-update metadata checks passed. Exact-version CI, hosted signing, integrity checks, and public-asset verification remain required before publication.

## Known Limitations

No real booking, external message delivery, or live microphone/API accuracy claim is made by these tests. Note and transcript content search remains bounded to keep typing responsive. Linked development folders reload manifest changes while Lima is running; extension declarations are not an operating-system sandbox. Arbitrary extension code is not automatically an AI tool: executable AI contributions require a supported host adapter and approval.

Existing Mail/Messages live-acceptance limits remain open. Scheduled work still requires Lima to be running and the Mac awake. Protected inputs, native permissions, payment commitments, and signed-update verification retain their existing boundaries.
