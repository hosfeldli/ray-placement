# Lima 4.2.0 — OpenCode and Better Search

This minor release adds OpenCode CLI compatibility and strengthens relevance ranking in Search, as requested on November 3, 2026. It is an incremental release and does not close the remaining broad Browser, Workbench, Mail/Messages, or live-device acceptance gates.

## New Features

- **OpenCode CLI provider:** Choose OpenCode in Assistant and AI Settings, use its existing local login, keep CLI default or select a `provider/model` ID, refresh its model catalog, and test the selected model.
- **Lima tools through OpenCode:** Chat history, tool requests, tool results, and continuations use Lima's existing routing and approval flow. The adapter agent denies OpenCode-native tools. Supported models can receive explicitly attached images and the latest screenshot continuation through temporary files.
- **OpenCode for Writing and Grammar:** Use the existing tool-free inference boundary without a separate Lima API key or endpoint. CLI errors remain visible.

## Improvements and Fixes

- Change CLI models directly beside the chat model menu. Claude aliases and saved custom IDs stay selectable; selections persist per provider and conversation.
- Launch Bun-installed CLIs with their runtime PATH and run Bun-managed Node-shebang launchers through Bun. AI Settings supports browsing to custom executable locations.

- Complete title words rank above prefixes of different words: for “terminal,” “Open Terminal” ranks above “Terminalizer.”
- Exact core-action keywords rank above weaker saved-content and prefix matches. Explicit user and extension aliases retain stronger priority; exact titles remain strongest.
- Multi-word matching consumes distinct words and considers longer tokens first, preventing repeated query words from being satisfied by one unrelated word.
- History and favorites remain bounded tie-breakers. Existing note search, scope filtering, and model selections are preserved.
- OpenCode discovery supports common installer, Bun, Homebrew, local-bin, and inherited PATH locations. Model IDs are validated and passed as separate arguments; prompts go over stdin.
- Ignore reasoning events as answers, combine visible text parts, and reject provider error events even when the CLI exits successfully. Retain bounded output, timeouts, cancellation, and temporary-file cleanup.

## Validation

All 855 discovered Swift tests passed in the isolated regression suite, including new Bun-launch and saved-model selection checks. Twenty-five final focused compatibility/provider and hosted-chat checks passed. Six earlier focused checks covered native tool loops for all three CLI providers after preserving inline provider configuration. An executable subprocess fixture covered model discovery and a complete Lima tool-call/continuation round trip. Eight provider settings renders covered both themes, narrow and wide layouts, and enlarged text. Twelve CLI chat renders covered all three providers in compact and full layouts. The official Bun 1.4.4 runtime ran a Node-shebang fixture without Node on PATH, preserving the model arguments. Signed updater metadata checks passed. The official OpenCode 1.19.5 binary accepted the adapter configuration with effective native tool denial in isolated temporary directories.

Exact-version CI, signing, artifact verification, and public-download verification remain required before publication.

## Known Limitations

No personal OpenCode login or live model request was used in compatibility tests. Use Test Connection to verify your installed CLI, account access, and selected model. Model-list membership does not prove access, and image support depends on the chosen model. OpenCode responses are delivered after each CLI request finishes; this adapter does not expose OpenCode's native terminal UI or reuse its session IDs. Lima carries conversation history and tool results explicitly between requests.

Use a trusted local CLI installation and configuration. CLI permissions are not an OS sandbox. Native permissions, protected inputs, exact-send reviews, financial-action checks, and signed-update verification remain in force. Existing live booking, Mail/Messages, dictation accuracy, and installed-update acceptance gaps remain open. Scheduled tasks still require Lima to be running and the Mac awake.
