# Lima v3.14.25 — embedded Browser and AI runtime preview

This release publishes verified portions of the post-v3.14.24 work. **It is not the complete AI Workbench described in the October proposals.** The user explicitly requested publication despite the open implementation and verification gates; the limitations below are part of the release scope, not completed features.

## Included

- Replaced the legacy Firefox Browser Bridge extension and native host with an embedded, user-visible WebKit Browser. It has independent Off, Read Only, Navigate, and Full Control AI modes; semantic page reads and frame-aware actions; bounded tab pooling, output storage, and screenshots; and guarded loopback HTTP for local previews.
- Added an opt-in, visible SwiftTerm PTY shared by the user and AI. The shell retains state and supports input, bounded reads and waits, status, resize, interrupt, and close. This is currently conversation-owned and confined to Lima's fixed Desktop workspace.
- Reduced synchronous Search keystroke work through actor-backed ranking. AI streaming batches events; large pasted text, Browser output, and screenshots have bounded/private storage paths; Markdown rendering moved off the main thread in supported paths.
- Added structured recovery hints for recognized Browser and Terminal failures and expanded automated regression coverage.

## Known incomplete or unverified scope

- This is **not** a persistent project-centered Workbench. Attached-folder security-scoped authority, full workspace access modes, network-enabled dependency installation, structured long-running process and port tracking, the broad native file/Git/web/HTTP/document/data/artifact tool suite, run-scoped plans, controlled shared-environment helper agents, a unified tool runtime, generic postconditions, and final-run evidence enforcement are incomplete.
- The AI execution engine is not yet the sole owner of approvals, cancellation, errors, and run lifecycle. Stored conversation bodies are still eagerly hydrated on the main actor when loaded.
- Browser tab suspension restores by URL rather than preserving full page state and history. Popup handling, real-site cross-origin/nested-frame geometry and clipping, accessibility, sensitive-action review, live provider compatibility, and manual Browser acceptance remain unverified. Some navigation acknowledgements explicitly report that the post-action state was not verified.
- The earlier Search/Workspace request document was unavailable during this release audit. Its complete scope could not be checked.
- Real-window frame pacing and memory comparisons for Search, AI streaming, Workspace switching, Notes edits, and resizing against immutable v3.14.24 were not completed. Synthetic Search probes improved MainActor keystroke time, but first-result measurements varied substantially with test load; earlier candidate runs were slower than v3.14.24. The October 16 baseline was not rerun under matching conditions. Do not interpret the fixtures as proof of real-UI performance.

## Verification performed before the source commit

- The full Swift suite passed **480 tests** on the current source tree.
- The Release configuration compiled successfully.
- Release-dispatcher and cloud-configuration checks, plist validation, release-metadata consistency, and staged/unstaged whitespace checks passed.
- The offscreen visual audit rendered **199 PNG fixtures with zero failed renders**. This does not replace real-site/manual Browser or real-window performance acceptance. The hosted release workflow must pass its build, test, signing, artifact, and remote-verification checks before publication.

Do not represent this release as fulfillment of every request since v3.14.24. The open gates are tracked in `docs/EMBEDDED_BROWSER_RELEASE_GATE.md`.
