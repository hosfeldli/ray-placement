# Lima 4.1.0 — A Clearer Workspace

Lima 4.1 reorganizes the app around **Assistant, Notes, and Recordings**, with a quieter Search surface and more capable AI tools.

## New Features

- **One Assistant workspace:** Move between conversation, Browser, and Terminal while keeping the same task. Wide windows can show the conversation beside the selected tool; compact windows use tabs.
- **Tasks for later:** Save a task with a future run time, expiration, and action settings. Review its state and results from Assistant settings. Due tasks run while Lima is open, the Mac is awake, and the conversation is available; this is not a background system wake service.
- **Live recording choices:** Use on-device transcription or rolling OpenAI API transcription with Lima's configured credential. Cloud speaker labels identify speakers within each audio window. Local participant names can be assigned manually.
- **Reusable captures:** Region screenshots and recognized text can be retained as references for later AI work, with quick capture actions available in Search.

## Improvements

- Three primary destinations, contextual recent items, and settings at the bottom of a simpler sidebar.
- Compact AI activity with expandable recorded history, one AI settings control, a bounded reading width, and cleaner attachments.
- A focused Notes editor, smaller formatting bar, Insert menu, and details shown on demand.
- Recording settings moved out of the transcript; completed recordings have fewer repeated banners and controls.
- Search now uses quieter surfaces, compact results, scope filters, optional details, and direct shortcuts to the three destinations.
- Extensions and utility search surfaces share the simpler visual language. Extension metadata loads in the background, cached lists avoid repeated grouping, and unchanged registrations avoid unnecessary writes.
- Browser interaction refinements cover dynamic navigation, embedded frames, semantic and visual actions, scrolling, stale observations, and bounded game-key holds.
- AI tools can discover implemented Lima surfaces, read permitted saved workspace data, and create or run visible terminal scripts in an existing absolute directory under their configured access policy.

## Fixes and Compatibility

- Older stock layouts migrate to the new defaults. Saved content and custom shortcut overrides remain compatible; Home opens Assistant.
- Browser and Terminal state remain owned by their existing services when switching views.
- Independent Browser task settings support eligible nonpayment actions; protected and financial actions retain their review boundaries.
- Signed artifacts and update metadata continue to use the existing hosted verification process.

## Validation

The candidate source passed all 800 discovered Swift tests, the focused 130-test regression selection, and 60 light/dark offscreen renders. Release versioning, hosted deployment-wrapper, and cloud-configuration checks passed locally. Exact-version CI and hosted artifact verification remain mandatory before publication.

## Known Limitations

This release publishes the implemented changes; it does not claim completion of every Browser, Workbench, or live-device acceptance gate. Automated tests and offscreen previews do not establish successful real-site reservations, game completion, microphone accuracy, API speaker accuracy, or installed-update acceptance.

Cloud recording uploads rolling audio windows, rather than providing word-by-word realtime streaming. Speaker labels are scoped to each window and do not establish a person's identity across a whole meeting. Local speaker names are manually assigned. API use requires a working configured key and model access.

Scheduled tasks require Lima to remain running and the Mac awake. A requested or dispatched website action is not proof of a confirmed booking. Browser screenshots, secure fields, financial actions, and native permissions retain their applicable protections.

Apple Mail and Messages retain the preview limitations disclosed in 4.0.0: Mail sending/replies have unresolved live acceptance and reconciliation; Messages native sending is text only, with attachment sending handled manually and no continuous incoming monitoring.
