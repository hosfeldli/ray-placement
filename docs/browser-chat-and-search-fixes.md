# Browser chat permissions, interaction, and Search sizing fixes

Independent Browser access now belongs to a conversation, instead of expiring at the end of one provider turn. Selecting it enables Browser Full Control and retains the grant for later turns and pages in that chat. Other chats start without that grant. The user can revoke it by selecting another approval mode; deleting the chat clears the saved grant. Each execution still receives a fresh run identity, so an old run cannot reuse the permission.

Saved tasks use a one-run approval override. Their saved choice neither grants nor revokes Independent access on the conversation. Payments, changed transaction terms, protected inputs, explicit tab pause, and user takeover retain their enforcement.

Current-tab activation now runs the site's actual click handlers rather than navigating directly to an anchor's URL. This preserves scripted reservation widgets and SPA links. Activation handles submit buttons through form submission, text inputs can be clicked to open date widgets, and pointer-down/up events support dropdown and calendar libraries. Hidden dialogs no longer incorrectly block visible targets. After a click starts a full navigation, observation waits for the loaded destination; partial readiness is reported accurately.

A live, non-booking Fogo check reproduced `stale_target` immediately after reading the homepage. Semantic actions now privately compare the original DOM node, its label/attributes/state/form context, and financial context when unrelated document mutations occur. Document, route, user, and snapshot identity checks remain. Changed or replaced controls, newly changed fee terms, occlusion, and protected inputs still invalidate actions. Screenshot/native visual guards remain separate. Frame actions also recheck the main document's transaction context. Semantic reads now inspect up to the existing 32-frame registration capacity instead of stopping at 12 and blocking common multi-frame pages.

Search's old presentation sizing deliberately latched the expanded height until the panel closed. It now follows the visible idle/results phase and preserves the top edge. The controller owns the native host's size, avoiding stale SwiftUI minimum sizes retaining the large background. The opening palette has more vertical space and bottom padding for its keyboard hint.

Validation includes chat persistence/isolation/revocation, saved-task overrides, a local HTTP multi-page embedded reservation flow with pointer-driven widgets and an actual fixture confirmation, dynamic-update and changed-terms checks, and native Search window expansion/collapse. An opt-in Fogo smoke test only navigates public pages and inspects controls; it does not enter personal data or submit a reservation. The Search visual audit covers light/dark, all densities, and normal/140% text at actual native panel sizes.

The live Fogo check passed navigation from the homepage to Reservations, opening the date picker, selecting a calendar day, and taking a current protected screenshot (1270×900). The reservation page had 15 accounted-for frames in the final check. No availability request, contact details, or reservation submission was made. Local fixture validation additionally completes a multi-page reservation and verifies its fixture confirmation. All 24 Search renders completed; native host tests verify repeated expansion/collapse and top-edge preservation.

Final validation: all 808 discovered Swift tests passed through `make test`; the opt-in live Fogo check passed separately after the final browser changes. Changes are local and have not been published as a new release.
